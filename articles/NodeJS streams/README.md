# Node.js streams на практике

Модуль Stream в Node.js - это один из самых эффективных модулей, доступных из коробки. Многие модули в Node.js под капотом используют стримы: например, `fs` или `http`. В интернете можно встретить довольно много полезных материалов для знакомства со стримами, однако в этой статье мы раскроем весь потенциал стримов на практических задачах с примерами. Если вы ещё не знакомы с основами, то можно начать погружение в стримы с материалов, доступных по ссылкам:

- [Node.js Streams для чайников или как работать с потоками](https://habr.com/ru/articles/479048/) (статья на habr, RU);
- [Node.js #6 Буфер и потоки (Buffer & Streams)](https://www.youtube.com/watch?v=r--VL8JywyA) (видео на youtube, RUS);
- [A Deep Dive into Node.js Streams | Masterclass](https://youtu.be/edB964-YYpE?si=nFIgpj2Fd63TuAoW) (видео на youtube, ENG).

## Введение

В статье мы рассмотрим применение на практике ключевых компонентов модуля `stream`, таких как: `Readable`, `Transform`, `Writable`, `pipeline`. В примерах можно познакомиться с некоторыми библиотеками, которые расширяют базовые возможности модуля `stream` для поддержки популярных форматов данных. Для каждой темы статьи доступны примеры кода по [ссылке](https://github.com/quazex/nestjs-learning/articles/NodeJS%20streams). Каждый пример доступен в виде тестового файла, который вы можете запустить локально. Особенно полезным для погружения в детали реализации будет использование дебаггера (настройки для VS Code включены в проект).

## Задачи

Каждый бэкенд разработчик рано или поздно сталкивается с задачей скачивания файлов клиентом или загрузки файлов на сервер. Если для статических файлов обычно достаточно настроить взаимодействие с хранилищем, то задачи с формированием и обработкой табличных файлов могут создать дополнительные сложности. В своей карьере мне встречались такого рода задачи:

- Формирование или обработка CSV отчета на десятки миллионов строк;
- Перенос/архивация содержимого больших баз данных;
- Трансформация большого объёма данных;
- Получение от клиента видео/zip файла на сотни мегабайт.

## Обработка CSV

CSV - это очень универсальный формат, в некотором роде стандарт для передачи табличных данных. Одна из главных особенностей CSV - это простота добавления новых строк. И если в JSON для представления списка необходимо обернуть все элементы квадратными скобками, то в CSV таких ограничений нет и любая строка - это текст между разделителями строк. Именно по этой причине CSV очень удобно обрабатывать в потоке, в котором каждый чанк данных - это строка файла.

Теперь давайте перейдем к реализации и посмотрим каким образом мы можем организовать получение и сохранение CSV файла в потоке.

## Строковый JSON aka JSONL

CSV отлично подход для плоских структур данных, особенно для визуального представления в Google Sheets или Excel. Но что делать, если каждый элемент потока может содержать сложные типы данных и нам очень нравится JSON для решения таких задач? Решение довольно простое и очевидное: если мы возьмем CSV, но в каждой строке будем хранить JSON объект, то получится идеальный формат для потоковой передачи со всеми преимуществами JSON. Именно по такому подходе и работает JSONL формат. Этот формат отлично подходит для взаимодействия между системами, например, при создании архивов или переносе данных между хранилищами.

## База данных

Теперь давайте детальней изучим возможности применения стримов в работе с MongoDB. Эта база данных из коробки позволяет выполнять чтение данных в потоке, но для записи данных поддержка стримов отсутствует. Нам необходимо создать собственную реализацию `Writable` стрима, который сможет эффективно решать задачу по согласованию потоков.

Стримы очень похожи на циклы, поэтому нам удобно переносить отдельно взятый элемент потока по pipeline. С другой стороны, во многих базах данных рекомендуется выполнять запись пачками для оптимизации скорости и потребления ресурсов. Таким образом, необходимо реализовать кастомный `Writable` на базе следующей схемы работы:

* Передаем ссылку на экземпляр подключения к базе данных в `Writable`;
* Получаем элемент потока и записываем во внутренний буффер;
* Проверяем наполнение буффера:
    * Если количество элементов ниже порога, то продолжаем получение данных;
    * Если выше - запускаем вставку данных в базу данных и очищаем буффер;
* В конце потока проверяем буффер и если осталось немного записей, то записываем их в базу и чистим буффер.

## Другие фишки

Классы стримов имеют ряд дополнительных возможностей, которые могут быт полезны в некоторых случаях:

- Статический метод `Readable.from` позволяет легко и быстро создать экземпляр из любого итерируемого объекта (например, массив или генератор);
- Конструкция `for...of` имеет встроенную поддержку обработки стримов, что поможет обойтись без коллбеков для обработки потока данных;
- Базовые классы стримов можно описать в аргументах конструктора, что может быть удобным для описания небольшой логики без наследования;
- У стримов есть полезные хуки (могут возвращать `Promise`), которые срабатывают в начале потока и после его окончания (например, сбросить внутренний буфер в конце потока);

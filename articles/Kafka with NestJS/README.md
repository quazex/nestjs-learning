# Кастомный транспорт для NestJS & Kafka

NestJS - очень популярный фреймворк для создания бэкенда на TypeScript. Этот фреймворк отлично подходит для создания проектов различной сложности и сегодня мы поговорим о больших проектах на базе микросервисной архитектуры. В интернете можно найти много различных материалов, в которых подробно раскрываются преимущества и недостатки микросервисной архитектуры, но в этой статье мы сфокусируемся на технической реализации с примерами. Вы можете скачать полностью функционирующий пример статьи из публичного репозитория, в котором можно найти массу других полезных материалов для знакомства с подходами в работе с NestJS.

## Задача

Давайте представим, что нам необходимо создать сервис для получения потока различных данных из Kafka и сохранения пачки данных в [ClickHouse](https://github.com/quazex/nestjs-clickhouse) для формирования статистики. Такая комбинация технологий отлично дополняет друг друга, потому что ClickHouse наиболее эффективен при вставке данных большими пачками, а Kafka помогает обеспечить такую доставку надежно. Учитывая поставленную задачу, нам необходимо получать множество сообщений за один раз, при этом допускается публикация сообщений как пачками, так и поштучно. 

## Мотивация
Почему мы будем создавать собственное решение вместо использования готового? Такой подход имеет ряд преимуществ и мы кратко рассмотрим каждое:
1. Наша задача заметно отличается от подходов в базовой интеграции с Kafka в пакете `@nestjs/microservices` (судя по исходному коду [KafkaServer](https://github.com/nestjs/nest/blob/master/packages/microservices/server/server-kafka.ts#L172) мы не можем настроить получение сообщений батчами);
1. Нам важно иметь бóльший контроль зависимостей для большей гибкости в будущем. На момент создания статьи доступно не так много клиентов для интеграции с Kafka, при этом в каждом есть свои заметные недостатки. Например, популярная библиотека [kafkajs](https://github.com/tulios/kafkajs) последний раз обновлялась два года назад, а [node-rdkafka](https://github.com/Blizzard/node-rdkafka) основана на [librdkafka](librdkafka), что может вызывать трудности при запуске проекта на различных платформах;
1. Мы хотим иметь доступ к экземпляру подключения для Health Check проверок (UPD: в версии 11.x `@nestjs/microservices` [появилась такая возможность](https://docs.nestjs.com/microservices/basics#underlying-driver-access)). Таким образом мы можем точно определить состояние подключения для принятия решений;
1. Возможность создать относительно простое решение под конкретную задачу, что повысит надежность и упростит будущую поддержку.

## Реализация
Отличной точкой старта можно считать знакомство с [официальной документацией](https://docs.nestjs.com/microservices/custom-transport), описывающей базовые подходы при создании транспорта для `@nestjs/microservices`. 

После знакомства с основами мы готовы приступить к созданию типового модуля для NestJS с динамической конфигурацией. Единственное отличие будет заключаться в классе, который мы будем использовать в main.ts для подключения к Kafka в рамках микросервисной архитектуры.

В структуру нашего модуля входят файлы:

```bash
server.context.ts.      # Настройка доступа к дополнительным полям запроса
server.decorators.ts    # Декораторы на базе @Inject для доступа к клиентам
server.indicator.ts     # Проверка подключения консюмера
server.interfaces.ts    # Типы для динамической конфигурации модуля
server.module.ts        # Модуль и его инициализация
server.pattern.ts       # Обертка для EventPattern с явным указанием транспорта
server.providers.ts     # Набор фабрик для генерации Injactable провайдеров
server.strategy.ts      # Сервер подписки и обработки входящих данных
server.tokens.ts        # Уникальные токены для управления компонентами модуля
server.transport.ts     # Идентификатор транспорты для разделения подписок
server.types.ts         # Различные типы
```
